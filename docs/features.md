# Признаки

Код: `backend/ml/features.py`, одна функция `build_features` и для обучения, и для прогноза.
Результат хранится в таблице `match_features` (версия набора `v1`, значения в JSONB).
Запуск: `docker compose run --rm --build ml`.

## Принцип без утечки

Матчи обрабатываются **по датам**. Для каждой даты сначала считаются признаки всех её матчей
из состояния клубов «на утро», и только потом состояние обновляется результатами этого дня.
Поэтому признак матча физически не может содержать ничего, что стало известно в день матча или позже.

## Признаки

| Группа | Признаки | Смысл |
|---|---|---|
| Календарные | `weekday`, `month`, `is_weekend`, `is_holiday_period` (20 дек – 3 янв), `days_into_season` | Когда играют. Час начала не используем: в CSV за сезон 2025/26 он расходится с API у 82 % матчей |
| Контекст | `is_derby` (из CSV, для неизвестных пар — по ранее виденным дерби) | Принципиальность матча |
| Лаговые, посещаемость | `att_last1`, `att_mean3`, `att_mean10` | Посещаемость прошлых домашних матчей на этом стадионе (только `ok`) |
| Оконные, посещаемость | `att_median_all`, `att_cap_proxy` (максимум за историю), `att_hist_n`, `att_days_since_hist` | Типичная заполняемость, оценка вместимости, длина и «свежесть» истории |
| Притяжение соперника | `away_pull` | Средняя заполняемость стадионов, на которых соперник играл в гостях (отношение к вместимости), последние 10 матчей |
| Форма | `h_ppg5`, `a_ppg5`, `h_gd5`, `a_gd5` | Очки и разница мячей за 5 последних матчей |
| Положение | `h_pos`, `a_pos`, `h_season_ppg`, `a_season_ppg`, `h_played`, `a_played` | Таблица **до матча**, посчитанная по результатам, а не взятая из CSV (там итоговая) |
| Сила клуба | `h_prev_ppg`, `a_prev_ppg` | Очки за игру в прошлом сезоне (пусто у новичков лиги) |
| Усталость | `rest_days_h`, `rest_days_a` | Дней с прошлого матча |
| Клуб | `home_team_id` | Категориальный, кодируется на этапе модели |
| Новости | `h_news_count`, `a_news_count`, `h_news_sent`, `a_news_sent` | Число статей о клубе за 7 дней до матча и их средняя тональность (VADER, шкала от −1 до 1) |

## Обоснования

- **Кодирование клуба: one-hot.** Порядка между клубами нет, поэтому порядковый код вводил бы ложную близость. Целевое кодирование
  (средняя посещаемость клуба) отвергнуто: оно использует целевую переменную и даёт утечку при неосторожной валидации. 46 категорий на ~7 600 строк для one-hot допустимы.
- **Тональность считается здесь, а не при сборе.** Пайплайн хранит сырой текст, а метод оценки можно менять без повторной загрузки.
  VADER выбран потому, что размеченных данных нет, а ему они не нужны.
- **Только достоверная посещаемость.** В истории стадиона участвуют матчи со статусом `ok`, недостоверные сезоны в лаги не попадают.

## Ограничения

- Новости появляются только с момента запуска сборщика, у всех матчей 2000–2022 новостных признаков нет (`count = 0`, тональность пуста).
  Поэтому в обучении они не несут информации и отсеиваются на этапе отбора признаков. Для прогноза будущих матчей они считаются и сохраняются.
- Для прогнозов на 2026/27 последняя достоверная история посещаемости относится к 2022/23 (`att_days_since_hist` > 1000).
  Качество в этом режиме оценивается отдельно.

## Доказательство отсутствия утечки

Тесты `backend/tests/test_features.py`:

1. **Усечение будущего.** Признаки матча, посчитанные по полной таблице, совпадают с признаками, посчитанными по таблице, из которой удалено всё после даты матча (а результаты матчей этого дня скрыты).
2. **Собственный исход.** Изменение счёта и посещаемости самого матча не меняет его признаков.
3. **Недостоверная посещаемость.** Подстановка абсурдных значений в матчи `suspect` не влияет ни на один признак.
4. **Новости.** Статьи, опубликованные в день матча и позже, игнорируются.

Чувствительность тестов проверена внесением намеренных утечек в копию кода (признак с посещаемостью самого матча, вместимость по будущим матчам, учёт недостоверных сезонов): тесты падают во всех трёх случаях.

Запуск: `cd backend && python -m pytest`.
